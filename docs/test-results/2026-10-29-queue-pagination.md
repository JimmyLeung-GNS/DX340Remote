# Full queue pagination

29 October2026, Asia/Shanghai. **VERIFIED for software and the actual DX340 source reads below. Phone BLE and current iOS compilation remain NOT TESTED.**

The preceding complete-queue check exposed101 Apple queue entries, while GET_QUEUE returned only its first50. This left later queue entries unreachable from the phone. This change preserves the source playback engine and adds bounded queue windows throughout the companion, shared Flutter UI, native Kotlin/Swift clients and their bridge snapshots.

## Implementation

GET_QUEUE accepts optional offset(default0), with revision required for positive offsets. Replies retain items/revision and add offset/total/nullable nextOffset. Old clients still receive the first window; new clients do not invent a continuation for older hosts. QueuePages returns up to50 complete entries within48KiB of encoded UTF-8 data; metadata-heavy pages shrink by actual encoded size, and nextOffset advances by the returned count. A single unrepresentable entry returns MESSAGE_TOO_LARGE. Queues above10000 entries return QUEUE_LIMIT. There is no title truncation or partial JSON.

The existing complete-queue revision includes source epoch, queue order, IDs, media identity and titles. Missing/changed revision on continuation fails STALE_LIBRARY. PLAY_QUEUE_ITEM continues revalidating current full queue/revision before and after source handoff. Paging never starts playback. The shared UI shows the current range/total, Next queue page and Start of queue, replacing each window. Duplicate reads/old-row selection are disabled while loading. Row callbacks retain their displayed revision; Dart rejects retained old-revision/off-page/mismatched-title rows. Native request IDs/source epochs/latest-request guards prevent older replies replacing a new source/window. Queue error clears actionable window data. Native Android malformed replies now disconnect, matching the existing Swift fail-closed behavior. New queue metadata/loading fields are additive within bridgeVersion1.

Protocol contract/schema: protocol/specification.md and protocol/schemas/request.schema.json. Native reference apps remain in the repository; only the shared controller is installed at build2.
